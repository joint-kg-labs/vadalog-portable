# ChaseBench — `STB-128` scenario, in Vadalog

A runnable transcription of the `STB-128` scenario of
[ChaseBench](https://github.com/dbunibas/chasebench) (`scenarios/STB-128`) into the
dialect accepted by `vadalog-portable`. The programs are versioned with the
repository; **the data is not** — it is 209 MB — so `fetch-data.sh` brings it down
from ChaseBench on demand. Nothing here ships in a wheel or a release, and whatever a
run writes under `out*/` is ignored by git. Provenance and citation:
[`../README.md`](../README.md).

`STB-128` is generated by [iBench](https://github.com/RJMillerLab/ibench) from a
catalogue of schema-mapping primitives, and the relation names still say which one
made them: `_cp_` copy, `_hp_` horizontal partition, `_vp_` vertical partition, `_su_`
add an attribute. The result is a data-exchange scenario of a size the other three
have nothing to compare with: **111 source relations of about 10 000 rows each, 160
source-to-target TGDs, 39 target TGDs and 93 target EGDs**. It is the one scenario
here that exercises TGDs with existentials, target recursion and key constraints at
the same time, over a million source facts.

## Files

| File | Contents |
|---|---|
| `rules.vada` | the 160 s-t TGDs, the 39 target TGDs and the EGDs |
| `inputs-10k.vada` | `@input` / `@bind` for the 111 source relations |
| `STB-128-10k.vada` | driver: inputs + rules + `@output` of all 176 derived relations |
| `STB-128-10k-queries.vada` | the same plus the twenty benchmark queries |
| `fetch-data.sh` | downloads and unpacks the source data into `data/10k` |

Each common-format EGD statement carries several equalities at once
(`… -> ?a = ?b, ?c = ?d`); a Vadalog EGD has one equality per rule, so the 93
statements become 193 rules sharing their bodies. That is the only structural change
in the transcription; query bodies are additionally reordered so the joins bind early,
as in the other scenarios.

## Running

```sh
sh fetch-data.sh                       # once: ~100 MB down, 209 MB unpacked
python3 ../../dist/vadalog.pyz run STB-128-10k.vada --format csv --out out-10k
python3 ../../dist/vadalog.pyz run STB-128-10k-queries.vada --format csv --out out-q10k
```

Every column is a string, so no `@mapping` is needed. Note that the full target
instance written by the first command is about 300 MB of CSV.

## Results obtained

1 109 037 source facts in; the chase closes in **3 rounds and 1 m 30 s** on CPython
3.10 with an instance of 3 046 258 facts, of which 1 937 221 are the 176 derived
relations; 419 700 candidate facts were suppressed by the isomorphism check. Running
the twenty queries on top costs nothing measurable: 1 m 28 s for chase and queries
together.

**The target constraints hold; twelve source-to-target TGDs do not.** An independent
check, written without the engine, read the engine's own output together with the
source CSVs and found the 39 target TGDs and all 93 target EGDs satisfied — the key
constraints, the part most likely to go wrong with existentials in play, come out
right — and reproduced all twenty answer counts exactly, the six empty queries
included, which are empty in the data rather than lost by the engine.

Twelve of the 160 source-to-target TGDs are violated, and they are all of one shape:
the vertical-partition rules, `garden_vp_3(A, B) -> slow_vp_3(A, C), word_vp_3(B, C)`,
whose two head atoms are tied together by an invented join attribute `C`. When two
source rows agree on the attribute that goes into one half, the two halves it would
produce are isomorphic, the termination check of SPECIFICATION.md §7.4 keeps only one,
and the surviving partner of the discarded one is left without its match. It is the
same mechanism as in [`LUBM`](../LUBM/) and [`deep`](../deep/), milder here because
almost every tuple carries constants alongside its null: 12 rules out of 160 rather
than all of them.

## Why there is no reduced instance

A prefix of each source relation would be small enough to commit, and it is worthless:
the generated cross-relation references point anywhere in the ten thousand rows, so on
a 200-row prefix the chase still runs (1.8 s, 61 034 facts) but fourteen of the twenty
queries return nothing. Either the scenario is run at its own scale or it is not run
at all, which is what `fetch-data.sh` is for.
